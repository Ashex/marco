E3: open from an evicted page cache

Every run starts with the snapshot's files dropped from the page cache. mmap prefault is ready when its populate thread ends; lazy and random when the server answers /readyz; the engine when it has registered every file (reading and checking the pinned sections) and, at Fits, loaded every page.

E4 and E5: the archive day under load, then a checkpoint

A hard-linked copy of the FORMAT 6 snapshot follows a fake Jetstream serving phase 3c's archive day (2.75M follow, block and list-item ops, the 24 h after the snapshot's cut) as fast as the server takes it, while the skewed v2 mix runs open loop at 50% of the variant's sustained rate in 5 s steps. The fake stamps the day with this run's times at 106 events/s, so the server is never short of events; it is caught up once every event is read and written (/readyz alone turns at once, since the first events land under a second old). Then one Admin.Checkpoint, timed to its job's end, switch included.

E4: a simulated week at full residency

Seven days, each from its own fake Jetstream at a fixed rate, then one checkpoint and whatever compaction the server schedules after it, under the skewed v2 load at 50% of sustained the whole time. Day 1 is the archive day; days 2-7 are made from it (internal/week_capture.py): the same actors creating as often, subjects from day 1's creates shuffled, each day deleting as many of the day before's records. H is the budget's free part before each checkpoint, so the switch gate is P_new + R ≤ free, which is G ≤ H − P_new − R.

Method

The load box: 32 threads, 61 GB, kernel 7.0, one NVMe. Snapshots are the whole network with follows, blocks and list items, both built from one archive export: FORMAT 5 (39.9 GB, phase 1's) and FORMAT 6 with slack blocks (44.1 GB, phase 3d's). FORMAT 5 runs use phase 1's binary; FORMAT 6 and engine runs this tree's. Each run is a transient systemd service with MemoryMax and no swap (page cache counted), started after every snapshot file is dropped from the page cache. A run warms with 8 closed-loop steps of 8 s at 512 in flight (the last three give the closed-loop max), then an open-loop ladder at 25-100% of that max plus steps at 50% and 90% of the case's references; sustained is the highest ladder rate with nothing capped, no errors and p50 under 1 ms. Requests are a seeded stream (mix seed 0, inputs seed 42, 2M draws), so every variant replays the same requests. Server: cores 0-7 and siblings (16 threads) or cores 0-3 (4 threads); the lean client on cores 8-15 and siblings.

Raw results: internal/raw-p6 (provisional/ during the crawl, official/ after it), FORMAT 5's provisional runs in internal/raw-storage. Scripts: internal/run-p6.sh, run-storage.sh, run-e6.sh, day_capture.py.
